# Digger — план по шагам

## Как работать
Одна сессия Claude Code = один шаг. Промт каждый раз один и тот же:

> Сделай следующий шаг из docs/ROADMAP.md.

Claude Code сам берёт первый шаг с `[ ]`, пишет тесты, код, проверяет, коммитит, пушит, отмечает шаг и пишет
«можно очищать чат». Тогда вводите `/clear` и тот же промт снова.
Если нужно конкретное: «Сделай шаг 3.2». Если что-то пошло не так: «Шаг 3.2 не прошёл на Win7: <что видно>».

Результаты с рабочего ПК (отчёты, скриншоты, логи) кладите в `my_reports/`, реальные фото и PDF для проверок —
в `my_test/`. Эти папки только на Mac, в интернет не попадают. Сообщите Claude Code: «Отчёт в my_reports/…».

## Проверки на Win7 — выездами
Рабочий ПК доступен раз в день, поэтому проверки на нём **не останавливают разработку** и делаются пачкой.
- **Один архив — один запуск — один файл.** В портативной сборке лежит «проверочный набор» (`checks/`,
  шаг 0.7). На работе: скачать последний архив с GitHub, распаковать, запустить `Проверка на работе.bat`,
  принести домой один файл `отчёт_<дата>.zip` → `my_reports/`. Набор сам запускает все проверки, готовые к
  этому дню; ошибка одной не останавливает остальные.
- **Шаг с меткой ★ добавляет свою проверку в набор** и сразу считается выполненным (`[x]`), если зелёный CI.
  Разработка идёт дальше, результат с Win7 разбирается, когда придёт отчёт.
- **Проверка обязана исключать повторный выезд**: при неудаче сама перебирает запасные варианты (другие версии
  библиотек, другие параметры) и пишет полную диагностику (текст ошибки, версии, системные сведения).
- **Ручные действия** (то, что нельзя автоматизировать: посмотреть окно, положить свои фото) перечислены в
  `checks/ЧТО СДЕЛАТЬ.txt` внутри архива — коротким списком на один выезд.
- **Шаги «Доводка по отчёту выезда N»** (0.11, 3.4, 8.3) Claude Code берёт, только когда отчёт лежит в
  `my_reports/`; пока его нет — пропускает и берёт следующий шаг с `[ ]`.
- **Выезд можно делать в любой день**: чем позже, тем больше проверок в наборе. Таблица — когда выезд даёт больше всего:

| Выезд | Лучше после шага | Что проверит набор | Что ждёт отчёта (остальное не ждёт) |
|---|---|---|---|
| 1 | 0.10 (минимум — 0.7) | система; самопроверка; окно; PP-OCR на своих вырезках (несколько наборов параметров, сравнение с Tesseract, время); программа с PP-OCR; проба сайтов из сети работы с сохранением страниц. Вручную: положить в `фото/` те же вырезки, что в `my_test/ocr/` на Mac (ответы — в именах файлов) | 0.11 |
| 2 | 3.3 | все адаптеры фазы 2 (бывш. 2.15) + скачивание и проверка PDF для эталонных чипов | 3.4 |
| 3 | 6.6 | полный поиск: 12 эталонных чипов + свои фото (`live_check`) | 8.3 |
| 4 | 7.11 | новое окно: снимки всех экранов, 10 своих фото от начала до конца; повтор `live_check` | 8.3 |

Формат шага: **Цель** · **Файлы** · **Тесты** · **Готово, когда**.

**Модель для шага** — метка в начале строки шага. Переключение в Claude Code: команда `/model`
(или запуск `claude --model sonnet` / `claude --model opus`).
- `Sonnet` (Sonnet 5.5) — обычные шаги: репозиторий и проверки, адаптеры сайтов по фикстурам, скачивание,
  инструменты, типовые окна.
- `Opus` (Opus 5.5) — шаги, где закладывается устройство программы или важны безопасность и точность.
- Claude Fable 5.1 — не по умолчанию: если Opus дважды не справился с шагом, переключиться и повторить шаг.
- Haiku 4.5 — не для шагов плана, только для коротких вопросов вне плана.
